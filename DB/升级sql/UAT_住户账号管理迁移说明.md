# UAT 住户账号管理增量迁移

本说明仅适用于经过确认的商城 UAT 目标库。先备份业务库及匹配配置，确认当前部署版本、原 47 项迁移台账、`li_member` / `li_wechat_identity`、`li_p0_audit`、`li_p0_consistency_guard` 和原生菜单/权限表；不得覆盖现有 UAT 数据或重跑历史 SQL。

按顺序执行本目录内：

1. `UAT_007_member_security.sql`：创建 Member 级会话截止表。该脚本不是可重复建表脚本；由迁移台账按文件 SHA-256 和目标库登记，同摘要已成功执行则跳过；同名不同摘要或未知已有表必须停止核对。
2. `UAT_008_resident_menu.sql`：在唯一有效的 `uat-root` 下创建用户管理、住户账号及启停授权元数据。重复运行保留已有一致记录，不修改任何角色授权；已有同名但内容不一致或根目录缺失时失败。执行账号需具备临时创建、执行和删除存储过程的权限。
3. `UAT_009_member_relation_indexes.sql`：为现有身份、店员及店铺关系添加非唯一索引，减少账号变更时无关记录被锁定。执行前检查目标库是否已有同名索引或等效索引；名称冲突时停止核对，不修改历史表或删除人工索引。MySQL DDL 可能逐条提交，失败后核实已完成项并前向修复。

`UAT_008` 通过事务保证菜单写入一致，但 MySQL 的 `CREATE PROCEDURE` 不属于该事务；如果执行失败，先检查迁移结果以及 `p0_install_resident_menu_008` 过程的归属，确认是本次中断留下的过程后再由数据库管理员处理，然后重新执行。不得删除不明来源的过程或覆盖人工菜单。

三个脚本均需在发布新 API 前完成；新版本会在会话校验时读取 `li_p0_member_security`，应用数据库账号须具备该表的 `SELECT`、`INSERT`、`UPDATE` 权限；表缺失或权限不足会导致受保护会话无法正常使用。新代码部署后由管理员在原生角色页面为相应角色授予结构父节点、住户账号查询及按需授予的“启用和停用会员”操作，启停权限需选择操作授权。新增菜单不会自动授予管理员或普通角色。

当前实现与冻结集成版一致，依赖 `p0.uat.enabled=true`、P0 阶段能力及服务端住户/商户应用配置；公司服务器若已调整运行模式或菜单根结构，须先核对等效安全约束并适配，不得关闭资源或会话检查。API 和页面部署版本须匹配；测试身份来源、真实微信及渠道能力以目标环境核验结果为准。

应用回滚前必须检查旧代码对新表及菜单的兼容性；保留账号停用记录和失效事实，不删除表或回退数据来复活旧会话。出现无法确认的兼容问题时停止回滚并制定前向修复方案。
