# 微信登录与 Mock 商城测试部署

公司 Linux 开发测试环境按 [DEPLOYMENT.md](DEPLOYMENT.md) 构建、初始化和运行，验证范围见 [VALIDATION.md](VALIDATION.md)。三个应用源码仓即可完成部署，不依赖个人 project-ops 工作区。真实微信凭据、HTTPS、网络和真机条件需由部署人员实际配置和验证。

`database/` 前 47 项和 `tools/ddl-plan.tsv` 来自此前交接包；`tools/ddl-plan-v2.tsv` 在其后增加住户账号相关的 007、009、008 三项。业务库和 Mock 账本库的目标及顺序以 v2 清单为准。Git 属性保留迁移文件和清单的原始字节，避免跨平台换行转换改变摘要。

`tools/migrate-mock-schema.sh` 默认执行前 49 项；初始化原生权限目录并建立唯一的 `uat-root` 菜单后，使用相同参数追加 `--phase complete`，执行最后的住户菜单迁移。两阶段都可重复运行，摘要不一致或已有未知迁移会停止。该脚本仅用于确认的独立 TEST／Mock 数据库，不导入业务或账号数据。

迁移、原生管理员和菜单初始化、独立资源登记、服务器配置与 API 生命周期均有对应工具。不要直接导入历史环境凭据、复用旧运行登记或覆盖已有测试库。已有数据的升级需单独核对，不能通过重建数据库来冒充迁移成功。
